# RinkImpact

**Spatial Player Evaluation & Expected Goals Modeling in the NHL**

RinkImpact is an applied hockey analytics project that uses NHL event-level data to evaluate offensive opportunities, player impact, and spatial patterns of play.

The project combines **expected-goals modeling, spatial and spatio-temporal analysis, model backtesting, player-level evaluation, and Monte Carlo simulation** in a reproducible analytics pipeline.

## Project Objective

The central question is:

> **How can NHL event data be used to quantify the quality and spatial characteristics of offensive opportunities generated by individual players?**

The project will build an expected-goals (xG) model from shot-level data and use those probabilities to evaluate player performance beyond observed goal totals.

The goal is not to reproduce an existing public xG model exactly. The goal is to demonstrate a rigorous end-to-end approach to sports-performance analytics: data engineering, feature development, predictive modeling, validation, spatial analysis, simulation, and communication.

## Phase 1 — Data Pipeline

Build a reproducible pipeline for acquiring and preparing NHL event-level data.

Initial data sources may include MoneyPuck and/or publicly available NHL play-by-play data.

Tasks:

* [ ] Acquire one complete NHL season
* [ ] Create reproducible ingestion scripts
* [ ] Standardize player and team identifiers
* [ ] Validate shot coordinates
* [ ] Standardize rink orientation
* [ ] Identify goals, shots, misses, and relevant events
* [ ] Validate missing values and unusual observations
* [ ] Create analysis-ready shot dataset
* [ ] Document data provenance and limitations

**Deliverable:** Clean, reproducible shot-level dataset.

---

## Phase 2 — Feature Engineering

Develop predictors describing the location and context of each scoring opportunity.

Candidate features:

* [ ] X/Y rink coordinates
* [ ] Shot distance
* [ ] Shot angle
* [ ] Shot type
* [ ] Period
* [ ] Time remaining
* [ ] Strength state
* [ ] Score differential
* [ ] Previous event
* [ ] Time since previous event
* [ ] Rebound indicator
* [ ] Rush indicator where derivable
* [ ] Shooter information
* [ ] Team/opponent context

Avoid using an existing provider's xG estimate as a predictor.

**Deliverable:** Modeling dataset with documented features.

---

## Phase 3 — Expected Goals Model

### Baseline

Build an interpretable logistic regression model:

`P(Goal) = f(distance, angle, shot type, game context, ...)`

This establishes a benchmark against which more complex models can be evaluated.

### Machine Learning Model

Train an XGBoost classifier using the engineered feature set.

Compare models using:

* ROC-AUC
* Precision-recall performance
* Log loss
* Brier score
* Calibration
* Out-of-sample performance

The objective is not simply to maximize classification accuracy. Predicted probabilities should represent meaningful estimates of scoring probability.

**Deliverable:** Validated expected-goals model.

---

## Phase 4 — Temporal Backtesting

Models should be evaluated against future observations rather than relying exclusively on random train/test splitting.

Example:

```text
Earlier games → Model training

Later games   → Holdout evaluation
```

Questions to investigate:

* Does model performance remain stable over time?
* Are predicted probabilities well calibrated?
* Does performance change across teams or game situations?
* Which features remain consistently predictive?

**Deliverable:** Model validation and backtesting report.

---

## Phase 5 — Spatial Hockey Analytics

Treat the rink as a spatial environment rather than simply using coordinates as two additional columns.

Develop:

* [ ] Shot-location maps
* [ ] Expected-goal spatial surfaces
* [ ] High-danger scoring regions
* [ ] Player shot-density maps
* [ ] Player vs. league-average spatial profiles
* [ ] Team/player spatial comparisons

Example research question:

> Where does a player generate scoring opportunities, and how does that spatial distribution differ from league-average offensive activity?

**Deliverable:** Publication-quality rink visualizations and player spatial profiles.

---

## Phase 6 — Player Impact

Aggregate shot-level predictions into player-level metrics.

Potential measures include:

**Expected Goals**

`xG = Σ P(goal_i)`

**Goals Above Expected**

`GAX = Goals - xG`

Additional measures may examine:

* Opportunity volume
* Average shot quality
* High-danger opportunity generation
* Spatial concentration
* Finishing relative to expected results
* Performance stability across time

Interpret player metrics cautiously because teammates, opponents, deployment, sample size, and game state can influence observed results.

**Deliverable:** Player evaluation framework.

---

## Phase 7 — Monte Carlo Simulation

Use estimated shot probabilities to simulate possible scoring outcomes.

For each scoring opportunity:

`Goal_i ~ Bernoulli(p = xG_i)`

Run repeated simulations to estimate distributions of possible outcomes.

Applications may include:

* Probability distributions for player goal totals
* Expected scoring ranges
* Observed vs. simulated performance
* Quantifying uncertainty around player outcomes

**Deliverable:** Simulation module and uncertainty analysis.

---

## Phase 8 — Advanced Modeling

This phase is optional and should only begin after the core project works.

Potential extensions:

* [ ] Hierarchical player models

* [ ] Bayesian player effects
* [ ] Partial pooling for low-sample players

* [ ] Team/context effects

These models should answer a clear hockey question rather than being added solely for technical complexity.

# Project Principles

### 1. Build the baseline first

Do not start with deep learning, Bayesian modeling, or elaborate simulation. Establish a clean dataset and credible baseline first.

### 2. Prevent data leakage

Features must represent information that would reasonably have been available at the time of the event being predicted.

### 3. Validate through time

Future observations should remain genuinely unseen during model development.

### 4. Evaluate probabilities, not just classifications

Expected-goals models are probability models. Calibration matters.

### 5. Make the hockey interpretation clear

Every model should answer an understandable hockey question.

### 6. Prefer depth over feature creep

A polished, validated xG + spatial player-evaluation system is more valuable than ten unfinished modeling experiments.

### 7. Be explicit about limitations

Public event data cannot reproduce the richness of proprietary player/puck tracking data. Results should be interpreted within those constraints.
